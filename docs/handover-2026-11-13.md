# Handover 2026-11-13: FrameMotion 0.1.2

## What happened

The owner approved a repair release of Creative Studio, FrameMotion and FrameCut after the dependency review of 2026-11-13, and added two working rules for reels: the reel workflow (plan, contact sheet, 540p preview, full render) and sound for reels (music and effects from code, a warning before third-party music, about −14 LUFS with the peak below −1 dB, limiting in numpy).

## Changes in 0.1.2

- `references/reel-workflow.md` (new) holds the four stages and the sound rules; `SKILL.md` step 5, the sound bullet, `claude-code-reels.md` and `motion-sound-design.md` point to it.
- `assets/sound-listen/place_sfx.py` limits with `motion-sound/synth.py`'s numpy look-ahead limiter (a numpy sample-peak fallback when that file is absent) instead of FFmpeg's `alimiter`.
- `references/first-setup.md` has its own runtime section, so the Animate engine and the starters install without Creative Studio's environment check; the workspace stays `~/.framecore-studio/workspace` so existing copies are reused.
- First setup also offers FrameCut, Open Assets and Creative Studio, and Toolbox's `rea-video` (Toolbox 1.15.0).
- Every link that named Creative Studio's removed `caption-studio` or `opencut-video-studio` paths now names FrameCut's paths as "FrameCut: `path`" text.
- Creative Studio 1.180.0 no longer lists FrameMotion in its own marketplace: it depends on `framemotion@framemotion`. INSTALL.md says how to replace an older `framemotion@framecore-works` copy.

## Verification

`python3 tools/check.py` (full) passes on the Mac with FFmpeg built with libass, numpy and a HOME without a Playwright cache. ChatGPT Work, Codex and the Claude apps: NOT_RUN in this release.

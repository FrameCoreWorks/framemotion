# room-at-dawn: techniques for the photoreal engine

Source: [Leonxlnx/room-at-dawn](https://github.com/Leonxlnx/room-at-dawn/tree/aab8be218aa051bbb2e22b82916962619c951747), commit `aab8be218aa051bbb2e22b82916962619c951747`, Copyright (c) 2026 Leon Lin, MIT ([licence](LICENSE)). Read at the source on 2026-11-14; nothing of it was run.

FrameMotion's photoreal blocks (`skills/framemotion/assets/engines/photoreal/`) adapt parts of it and are rewritten on the FrameMotion engine kit: `bake.mjs` (per-vertex light baked by CPU path tracing over a BVH, with the sun, area lights and window portals sampled directly, read again from source on 2026-11-16), `gi-material.mjs` (the material patch that adds the baked light and box-projects reflections), `accum-camera.mjs` (sub-frame accumulation with Halton pixel jitter, a thin-lens aperture and projection shear around the focus plane, a 180° shutter) and `film-grade.mjs` (bloom from a mip pyramid, vignette before the curve, tonal-range tint, Uchimura's filmic curve, highlight-weighted grain and a dither). Each file's header names this source; the changes are FrameCore Works code under Apache-2.0, and the MIT notice above travels with them. The grain hash is David Hoskins' "Hash without Sine" (MIT).

Left out on purpose: its helper server (it runs ffmpeg with arguments sent from the browser page), the room scene and its geometry, the HDR10 path, and all sound (CC BY and public domain recordings). Our bake differs from the source: each point has its own seeded random stream so the result does not depend on the number of workers, the patch is per material instead of editing three's shared shader chunks, it stops when three.js changed the code it edits, and the test scene (`photoreal/room/`) is our own, not the source's room.

# Changelog

## 0.9.0 (in progress, 2026-11-23)

Owner request 2026-11-23: port the Haskell library Reanimate (public domain) as FrameMotion's own engine, "a 1:1 base that draws the same pictures, adapted to our reels". Five packs; this entry grows with each one.

- Pack 1, the core: a new engine `reanimate` (registry group `explainers`, `experimental`): SVG trees and Reanimate's SVG printer, paths and partial drawing, Bézier arc length, layout, time, signals, effects, transitions, scenes, variables and sprites, and 57 of Reanimate's documentation examples (setting `example`). The page takes `screen` (canvas in units; without it the short side is 9 units, so 1080x1920 gives a [9, 16] reel) and refuses a `screen` whose proportions differ from the frame.
- Ported, with licences and pins in `integrations/`: Reanimate (Unlicense), svg-tree's printer and colour table (BSD-3-Clause), cubicbezier's Bézier code and arc length (BSD-3-Clause), Text.XML.Light's element printer (BSD-3-Clause) and linear's `lerp` order (BSD-3-Clause). AGENTS.md rule 6 names the accepted public-domain dedications as a closed list (Unlicense, CC0-1.0, 0BSD).
- QA, pack 1: the 54 examples with a Reanimate golden file print byte-identical SVG (10 frames each). Against the documentation GIFs at 320x180, frame i at i/25 s, mean grey difference 0.0 to 0.4 on a 0 to 255 scale for all examples but three: `pathify` 3.69 (the GIF predates the current `gridLayout`), `mkText` 1.06 and `queryNow` 1.02 (fonts). Of the three examples without a golden file, `powerS` (0.01) and `spriteScope` (0.04, worst frame 0.18) match their GIFs; `signalS` has neither a golden file nor a GIF and is covered only by its duration and frame checks. `arcLength` is ported from cubicbezier's source; no golden file has an asymmetric curve drawn in part, so its agreement with Reanimate there is read from the code, not measured (a test pins it within 2e-5 of the true length of an asymmetric curve).
- Pack 2, objects, colours and text: objects with position, margins, opacity, scale and easing, their animators (`oDraw`, `oGrow`, `oScaleIn`, `oScaleOut`, `oFadeIn`, `oFadeOut`, staggering) and the camera; colour spaces (sRGB, CIE XYZ, CIE L*a*b*, LCh, HSV, ported from the Haskell package colour 2.3.6, MIT), colour components and 11 colour maps; `latex`, `math` and `latexAlign` drawn as glyph outlines by MathJax 3.2.2 on the engine page (new npm dependency of the engines, Apache-2.0, about 24 MB installed; Reanimate uses LaTeX and dvisvgm). 26 more examples (83 in all). Parula is left out (MathWorks design, unclear licence). Fix found on the way: a scene that moves its clock back (`wait` with a negative time) now lasts to the latest time the clock reached, as in Reanimate.
- QA, pack 2: the 16 colour examples with golden files match Reanimate (SVG byte for byte, embedded PNG pixels identical; the PNG bytes differ because Reanimate's zlib compresses them). Against the documentation GIFs: colour examples 0.0 to 0.34, `cameraAttach` 0.16 and `cameraFocus` 0.25 (mean grey difference, 0 to 255). TeX examples 1.3 to 7.4: the letters are the same Computer Modern shapes from MathJax's fonts, but outlines start elsewhere (so `oDraw` traces a different route), and the 2020 `oDraw` GIF shows a thinner outline than the pinned code draws (see the engine README). `signalO` has no GIF; it is checked for its 3 s length.
- Pack 2 review fixes: TeX problems are reported, never drawn or dropped. A letter MathJax's TeX fonts lack (Polish ą, ę, ł; emoji) stops `latex` with the letters named, as LaTeX stops; ó, ś, ć, ń, ź, ż and other accented Latin letters are written as TeX accents and drawn. TeX errors, undefined commands and equation tags (`\tag`) throw with MathJax's message. Without MathJax on the page, a frame that draws TeX fails with install instructions instead of falling back to plain text. A NaN colour component (an LCh hue of grey) quantizes to 0 as GHC rounds it, and `encodePng` refuses a pixel that is not three bytes. An empty text given to `oDraw` and the other staggered animators says it has no glyphs. turbo, cividis and sinebow are credited in NOTICE to d3-scale-chromatic 3.1.0 (ISC; its licence text is in `integrations/d3-scale-chromatic/`) and turbo's design to Google (Apache-2.0). ISC is not on AGENTS.md rule 6's list; adding it is the owner's decision, so the source has no `sources.json` entry until then. Tests: every one of the 83 examples renders 10 frames at its pinned length with no NaN; the page pins the TeX examples' lengths; new checks for the camera's pan and zoom, `oShrink`, `oStaggerRev`, `interpolateRGBA8` and `signalO`'s 3 s.
- Pack 3, map projections: all 20 projections Reanimate has (August, Bonne, Bottomley, Cassini, Collignon, the equal-area cylinder, Eckert I, III and V, equirectangular, Fahey, Foucaut, Hammer, Lagrange, Lambert, Mercator, Mollweide, the orthographic globe, sinusoidal and Werner), each redrawing Reanimate's built-in Earth image pixel by pixel with Haskell's rounding; blends between two projections (`interpP`, `interpBBP`, `mergeP`) and the projection helpers; GeoJSON outlines bent by a projection (`drawFeatureCollection`, `applyProjection`). 20 more examples (103 in all), each a one-second still; on a reel screen the 16 x 9 picture is fitted whole and centred, keeping Reanimate's proportions. The Earth image's pixels are kept in the engine (about 190 KB); the country and land data of Reanimate's `map-projection` film is not in its repository and comes with that film in pack 5.
- QA, pack 3: Reanimate has no golden files for the projections; against its documentation GIFs the 20 stills differ by 0.7 to 2.0 grey levels of 255 (mean), from the GIF palette and the anti-aliased edge of the map; the pixels of each projected image are pinned in `tests/reanimate-geo.test.mjs`.
- Pack 3 review fixes: on a reel screen the map examples fit Reanimate's 16 x 9 picture whole and centred (a test measures it) instead of showing its middle; `applyProjection` refuses latitudes outside ±π/2 (GeoJSON still in degrees) instead of drawing NaN; `smallEarth()` returns its own copy; MathJax that fails to start makes only TeX frames fail, with the reason; a wrong "undefined command" error for `\color` in text is gone; the NaN check of every example skips embedded image data. The README lists the projection quirks kept from Reanimate and says the pixel hashes are a regression test. The ISC note in AGENTS.md rule 6 was taken back for the owner to decide.
- Pack 4, mathematics: six examples from Reanimate's examples folder. `fourier` (a square wave built from 1 to 100 rotating circles), `fourier_draw` and `tut_glue_fourier` (the letter π drawn by up to 501 Fourier circles, its coefficients from Haskell's `Data.Complex` step by step), `demo_tangent` (the tangent and normal sliding along the letter s, with cubicbezier's Bernstein evaluation), `demo_stars` (1000 stars placed with Haskell's own random numbers: random 1.2.0 over SplitMix, as Reanimate's resolver pins them, with 10 fading trail frames) and `balloon` (shapes inflated from one point). Under them: exact fractions (`Rational` as BigInt), polygons with shortest-path trees, outlines with holes cut in, Bézier clipping and closest points from cubicbezier, `atPartial`, and `nmToColor` with Reanimate's wavelength tables. `tangent_and_normal` is commented out upstream (it needs the diagrams library) and is not ported. The examples that compute with glyph outlines need a TeX renderer; in Node `useMathJaxNode()` plugs in the same MathJax as the page, and without one they stop with a clear message. Ported with pins: random 1.2.0 and splitmix 0.1.0.4 (BSD-3-Clause, Hackage).
- QA, pack 4: `balloon` against Reanimate's documentation GIF: mean grey difference 3.25 of 255 over 150 frames (the TeX outline of the X and the GIF palette; the same corner and pace). The other five have no golden file or GIF; their frames were checked by eye (contact sheet) and three frames of each are pinned as a regression test in `tests/reanimate-math.test.mjs`, with unit checks of the pieces (SplitMix's documented `mkStdGen 137`, Bézier-clipping roots, shortest paths around a corner, ties-to-even rounding of fractions, a hole cut into its outline). Differences on purpose: polygons are triangulated by ear clipping instead of hgeometry (the shortest-path tree is the same on any correct triangulation), zero-width hairs in an outline are dropped, and a path command with no points ends the path data instead of writing invalid SVG.
- Review fixes, pack 4: the ear clipping now handles outlines joined to their holes by a cut (the cut's repeated points, coordinates within 1e-9 made equal, no diagonal across an edge, and an exact check that the triangles cover the polygon); before, "e" and "8" got overlapping triangles and shortest paths that changed with the starting vertex by up to 4.8 units. Tested on 66 letters, digits and signs, and in `tests/reanimate-math.test.mjs`. `demo_stars` keeps only the source frames of the current trail (600 frames: 1.1 GB of memory before, 11 MB now). Fractions round correctly to subnormal doubles. The wavelength tables are named as what they are, CVRL's CIE 2012 and Stockman & Sharpe tables, whose licence CVRL does not state. cubicbezier and linear note the versions Reanimate's resolver pins (0.6.0.6 and 1.21.6, the same ported code).
- Pack 5, morphs, films and reel formats: shape morphing (`morph` with `linear`, `rawLinear` and `rotationalTrajectory`, point and object correspondences, colours blended in L*a*b*, the `Morph` object and `oTransform`) and Reanimate's 11 morphology examples; the 12 remaining examples with golden files (`bug_play1` to `3`, `bug_quad`, `counter`, `goo` with SVG filters (`mkFilter`, `feGaussianBlur`, `feColorMatrix`, `feComposite`), `intro_hello`, `raster`, `intro_canvas`, `intro_canvas_square`, `latex_basic`, `fe_morph`); the map-projection film (`map_projection_gif`, `map_projection_distortion`, 59 s through 17 projections) with Natural Earth's 1:110m borders and land (public domain, 289 KB, `core/natural-earth-data.mjs`); the showcase film (`showcase`: the sphere POV-Ray renders is drawn by FrameMotion's own `core/sphere.mjs`; `showcase_latex`: equations drawn glyph by glyph). Not ported: `sizes.hs` (a Blender globe), the logo examples and scenes (GitHub, Haskell, SVG marks). Reel formats: `R.REEL_FORMATS` (16:9, 9:16, 1:1, 4:5) and the page setting `fit` (`contain`, `cover`, `none`) with `R.fitScreenA`. 136 examples in all.
- QA, pack 5: the 8 new examples with golden files that draw no TeX match Reanimate byte for byte (78 golden files in all; `raster`'s PNG pixel for pixel). `linear`, `rawLinear` and `rotationalTrajectory` against Reanimate's documentation GIFs: mean grey difference about 8 of 255, 6.4 already on the still X (MathJax's X is not LaTeX's). The other morphs, the TeX pictures and the films have no golden file or GIF: checked by eye on contact sheets (the canvas introduction's grid, brackets and dot labels line up with its LaTeX golden file), three frames of each pinned, and the parts tested (sphere drawing, reel fitting, `oTransform` timing). Rendered through the engine kit in 9:16 (`fit: contain`), 4:5 (`cover`) and 1:1. Kept from Reanimate or fixed where it fails, all listed in the engine README: its `linear` serializes unrotated points (so here `linear` applies the closest rotation on purpose); `featLaTeX` fails there on `pause 0` (here it runs); Bottomley's pole line is 0/0 (left out instead of printing NaN). Natural Earth's public-domain map data is admitted by owner decision 2026-11-25 (AGENTS.md rule 6).

## 0.5.0 (2026-11-19)

- **Reel workflow, version 2** (owner messages 2026-11-19: the stages of a reel and the quality loop). `references/reel-workflow.md` is rewritten as the one source of truth: work as a motion designer, a film editor and a composer at once; five stages, four of them shown for acceptance: (1) idea and look in one package (hook, firm scene times, two or three finished key frames, music direction from the user's music profile, one reference asked for; two or three concepts with a named wow for an ad without an idea, exactly one for a precise brief), (2) the music as an MP3 composed to the plan's times (-14 LUFS, true peak below -1 dBTP, original or CC0, real instrument timbres, effects only sketched), (3) a contact sheet on the music's beats whose acceptance is the picture lock, (4) the 540p preview with full effects and the final mix (music may change its sound on the same grid; a new grid goes back to stage 2), (5) the 1080 render only on explicit request. Correction rules: notes collected per stage, at most two user rounds, a third means back to stage 1, notes become rule corrections in the user's own files and the music profile, process changes from the next project. The quality loop before every stage: each profession's checklist (frame strips at 4 to 5 fps with automatic checks on every frame and close-ups at text and cuts; cuts on the beat; loudness, grid, spectrum and a mono fold-down by measurement), then a fresh reviewer with only the brief, frames and measurements (score below 8 means fix), at most three passes, and one sentence on what the loop fixed and the weakest spot. New `templates/music-profile.md`. Sound sources follow the owner's rulings of the same day in the shared compendium: music is a CC0 recording with real instruments when one fits, otherwise composed in code and played by real CC0 instruments, never a Content ID library, and the stage 2 MP3 is the listening sample before the preview; effects for real objects are recordings of that object, code only for abstract accents. `motion-sound-design.md` (timing first instead of picture first), `layered-work.md` (layers mapped to the new stages) and `SKILL.md` follow it.

Nothing is bundled: `sound.py mix` fetches only the instruments the recipe uses into `~/.cache/framemotion/samples` (or `$FRAMEMOTION_SAMPLES`), checks size and git blob hash; offline, the same notes are synthesized and the mix says so. Several source folders name files an octave below the sounding pitch; the manifest stores the measured pitch. New `tests/motion_samples_test.py` and `tests/reel_workflow_test.py`.
- Evidence: licence read from the repository (GitHub licence field CC0-1.0, README credits) on 2026-11-19; piano, strings and pizz-bass fetched on the Mac (51 MB) and `samples.py verify` measured the sounding pitch of every zone in the measurable range within 0.12 semitone (one low violin note reads its second harmonic; its spectrum shows the 220 Hz series, so the zone is right); a 12 s test bed rendered with real piano, strings and bass.
